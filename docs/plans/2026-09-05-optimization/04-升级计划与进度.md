# 升级计划与进度（2026-09-07）

> 分支 `feat/2026-09-review-upgrade`。本文件按任务书 §5/§7 结构：产品判断 → 候选排序 → 逐项进度 → 需要用户决策 → 阶段完成记录。

## 1. 产品判断

### 1.1 目标用户

中国求职者，四类场景：**校招**（应届/实习，简历从零起步，最需要"第一版"）、**社招**（有经历，最需要针对 JD 定制与量化改写）、**跳槽**（在职、并行投递多家，最需要进度管理与面试准备）、**转行**（需要把旧经历翻译成新岗位的语言，最依赖知识库里的岗位画像）。其中一部分要投外企，需要英文简历与英文界面。

他们自带模型 API Key、接受本地存储——说明是有一定技术接受度的早期用户，但**动机是拿 offer 而不是玩工具**：任何一步的摩擦都会换算成"不如直接用 Word"。

### 1.2 核心闭环与当前最大摩擦

| 环节 | 现状 | 最大摩擦 |
|---|---|---|
| 写好简历 | 导入 / AI 生成 / 空白模板；聊天式 AI 改写 | 要改某一条经历，得先在聊天框里描述"第几段第几条怎么改"；首次打开没有引导，没配 Key 时 AI 全部静默失败 |
| 针对 JD 定制 | JD 匹配分析 → 一键优化 / 派生副本 | 派生副本多了以后，分不清哪一版投了哪家；改联系方式要每份改一遍 |
| 投出去 | PDF / DOCX / HTML / MD / TXT / JSON | 导出后没有"这一版长什么样"的记录；`resume_versions` 表存在但从未写入 |
| 记住进展 | 求职动态（列表 / 看板 / 图谱）、7 天日程 | 投递记录只关联"简历 id"，不关联"当时那一版" |
| 面试前准备 | 模拟面试、知识库公司/岗位页 | 材料分散在三处（投递 JD、知识页、简历），面试前要自己拼 |
| 复盘沉淀 | 复盘 → 经验页 + SOP 修订提案 | 复盘拿到的"当时简历"必然是当前简历（快照缺失） |

### 1.3 什么让人天天打开、推荐给朋友；什么让人一次就流失

- **天天打开**：求职动态的"接下来 7 天"和跟进提醒是唯一的每日回访理由；AI 记得"我投过哪里、上次面试问了什么"是别的工具给不了的。
- **推荐给朋友**：导出的 PDF/DOCX 在 HR 那边看起来就是专业简历（第二阶段修的双边距/Letter 纸/标题色，全是这条线上的）；"投给 XX 的那一版"能一键找回。
- **一次就流失**：① 第一次打开空空如也，不知道从哪开始；② 配错 Key 后所有 AI 功能报一串英文 401；③ 数据只在本机、没有一键备份——换电脑或误删就是全部心血。

## 2. 升级项进度

### U1 版本历史 — 完成 `ec742bc`

- **为什么**：需求 #6 的占位、需求 #10 复盘的"当时简历"、投递记录的"投给 XX 的那一版"三个缺口共用同一份数据；`resume_versions` 表存在但从未写入。
- **怎么做**：迁移 008（去掉 event CHECK、加 label/content_hash、applications.resume_version_id）；`db/repo/version.rs`：`update_resume` 每次落库留快照（内容 hash 未变不记；十分钟内连续自动保存合并为一条）；导出 / 关联投递 / 采纳 AI 修改显式留带标签的版本；恢复前自动存「恢复前」版本。UI：`文件 ▾ 版本历史` 对话框（时间线 + A4 预览 + 确认恢复 → 重载编辑器并清空撤销栈）；投递记录「查看投递时的简历版本」跳到该版；复盘优先用关联版本。
- **验证**：4 个 Rust 单测（重复保存跳过、会话合并、恢复保留模块 id、投递快照定位）；完整验收串通过。
- **待人工验收**：桌面里连续编辑 10 分钟只出现一条「保存」版本；恢复后撤销栈为空；投递记录里的链接能打开对应版本。

### U2 全量备份与恢复 — 完成 `b08c332`

- **为什么**：本地优先产品的生命线；此前只能逐份导出 JSON，知识库与设置无法迁移。
- **怎么做**：`commands/backup.rs`：`VACUUM INTO` 复制数据库（WAL 安全）+ `knowledge/` + localStorage 设置（`jade_*`、语言）→ 带 manifest 的 zip。恢复：校验 manifest / SQLite 头 / zip 路径穿越；先把当前数据自动备份到 `backups/pre-restore-*.zip`；知识库解压到临时目录后整体换入；数据库写成 `reseumer.db.pending`，启动时（打开连接前）原子替换；前端写回设置后强制重启。入口：设置 → 数据与备份。
- **验证**：2 个单测（路径穿越拒绝、pending 库启动替换）；完整验收串通过。
- **待人工验收**：导出 → 删几份简历 → 恢复 → 重启后数据回来、API Key 仍在；`backups/` 里有恢复前的 zip。

### U3 逐条 AI 改写 — 完成 `a3ddbaa`

- **为什么**：改一条经历要先在聊天框里描述"第几段第几条"，这是"写好简历"环节最高频的摩擦。
- **怎么做**：工作经历 / 项目 / 教育亮点、描述、个人简介旁的 ✨ 菜单：量化改写 / STAR 化 / 换用 JD 原词。不新建 AI 通道：`lib/ai-rewrite.ts` 生成带 sectionId 与原文的精确指令交给右侧助手，走既有 updateSection → 提案卡；指令随简历语言切换；"绝不编造数字"写进指令。
- **验证**：8 条指令断言；完整验收串通过。
- **待人工验收**：点「量化改写」后助手只改那一条并弹提案卡；采纳后版本历史出现「AI 修改」版本。

### U4 AI 错误可读原因 + 诊断信息 — 完成 `8390c6b`

- **为什么**：自带 Key 的用户每天撞 401/429/模型不支持工具，此前只看到一串英文原文。
- **怎么做**：`lib/ai-error.ts` 分类十类错误，错误面板下方给中英文可执行提示；每条错误可「复制诊断信息」（版本、平台、渠道、Base URL 主机名、模型、联网模式、原始错误，不含 Key）。
- **验证**：13 条分类断言；完整验收串通过。

### U5 首次启动引导 — 完成 `f3f0f6c`

- **为什么**：第一次打开空空如也、没配 Key 时 AI 全部失败、没写求职目标时 AI 不知道该往哪定向——三个流失点。
- **怎么做**：仪表盘顶部「三步开始」清单：配置模型（缺 Key）→ 第一份简历（无简历）→ 求职目标（purpose.md 全空），每步一键跳转（设置 / 新建 / 知识库 purpose.md 直接进入编辑态）；全部完成或「不再显示」后消失。取舍：不做多步向导，避免把有经验的用户困在流程里。
- **验证**：完整验收串通过。**待人工验收**：全新数据目录启动 → 三步依次完成后清单消失。

### U6 CI — 完成 `4b3f62d`

- `.github/workflows/ci.yml`：PR 与 main / feat / fix 分支推送时跑 type-check / lint / 前端断言 / `cargo fmt --check` / `cargo clippy -D warnings` / `cargo test` / vite build，与本地验收串同一组命令。**待人工验收**：首次在 GitHub 上跑通（Linux 需要 WebKitGTK，已在 workflow 里安装）。

### U7 面试准备包 — 完成 `fd5c5fc`

- **怎么做**：`knowledge_interview_prep` 复用复盘的事实收集，面试教练提示词输出 Markdown 准备单（公司速览 / 本轮考察重点 / 可讲的 STAR 故事 / 高频题与要点 / 薄弱处 / 反问），写入 `wiki/experiences/prep-*.md` 并进 FTS；投递记录操作区「面试准备包」按钮，成功后跳转知识库打开该页。准备单就是 vault 里的 Markdown 文件（即 MD 导出）；PDF 导出未做——知识页目前没有打印样式，属后续项。

### 用户反馈追加（2026-09-10）

用户在 U1–U7 之后提出四条：字体默认列表、Word 式选区格式化、编辑/预览焦点不同步与单行输入框、右栏条目顺序。判断：#2 背后的真问题是"结构化字段 + 全局主题"与"选中一段改它"的心智冲突，照搬 Word 会毁掉 AI 改写与多格式导出的基础；选择"选中即格式化，但结果存成字段内的内联标记，四端同一套渲染"。#3/#4 是同一个缺口：右栏没有"正在编辑哪一条"的概念。

- **F1 字体（`92560a2`）**：中文 8 种（微软雅黑 / 思源黑体内置 / 宋体 / 思源宋体内置 / 华文中宋 / 黑体 / 楷体 / 仿宋）× 西文 4 种（Calibri / Aptos / Times New Roman / Arial）独立选择；旧配对方案与旧 fontFamily 自动迁移；DOCX 字体名跟随；15 条断言。**待人工验收**：Windows 上华文中宋/Aptos 未安装时预览退回内置思源；WPS 打开 DOCX 字体名正确。
- **F2 选区格式化（`64d31e7`）**：描述与亮点字段选中文字浮出迷你工具条（B/I/U/颜色/字号/中文字体/清除格式），结果为 `{{color=…}}`/`{{size=…}}`/`{{font=…}}` 标记，预览/PDF/DOCX/TXT/MD 五端同规格（14 条前端断言 + 4 个 Rust 用例含 DOCX Run 属性）；助手提示词要求改写时保留标记。**取舍**：不做段落级"间距"选区属性（间距在排版工具条里全局设置）；不支持在预览里直接选中（DOM 选区无法可靠映射回字段字符串）。**待人工验收**：选中 → 点颜色 → 预览即时变色、导出 DOCX 后 Run 颜色一致；输入法状态下选区工具条不抢焦点。
- **F3 焦点联动 + 输入框增高（`f81ab0f`）**：活动条目双向联动（右栏编辑 → 预览高亮并滚动；预览点击 → 右栏展开并滚动）；单行输入框聚焦按内容增高、失焦回一行；亮点行回车新增下一条。
- **F4 条目卡片（`f81ab0f`）**：六个条目模块统一为可折叠卡片：拖柄 / 序号 / 摘要 / 上下移 / 上方插入 / 删除都在标题栏，非活动条目折叠。**待人工验收**：五条以上经历时拖拽排序一眼可见；新增条目自动展开并聚焦。

- **模板体系（U10）**：新增中式模板（左窄栏双栏、国企证件照版、英文 Harvard 风格）设计质量必须人工视觉验收，本轮不做；请决定是否单独立项并提供参考样张。
