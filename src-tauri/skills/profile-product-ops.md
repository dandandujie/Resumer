# 岗位画像：产品 / 运营岗

> 产品经理、用户/内容/活动/电商运营、增长等岗位的简历定向优化知识。

## 筛选者是谁
- 初筛后通常是业务负责人看简历，他们最关心：**你做的事和我的业务像不像、数字是否可信、有没有方法论**。
- 产品/运营岗简历供给远大于需求（尤其 3 年内），无量化数据的简历几乎必被淘汰。

## 经历写法
- 铁律：全程数据说话。每条经历「目标 → 动作/策略 → 数据结果」：
  - 弱：负责社区内容运营，提升了用户活跃
  - 强：搭建 UGC 激励体系（分层任务+创作者等级），3 个月内日均投稿量从 1.2k 提升至 4.5k，内容互动率 +38%
- 核心指标词：DAU/MAU、留存（次日/7日/30日）、转化率、GMV、ROI、LTV、CAC、渗透率、NPS。
- 方法论显性化但不堆砌：AARRR、RFM、A/B 实验、用户分层、漏斗分析——在具体动作中带出，不要单列"熟悉XX方法论"。
- 产品岗：写清「从 0 到 1」还是「从 1 到 100」，是否独立负责模块、协调过多大的研发资源（XX 人团队/XX 人日）。

## 分方向侧重
- **产品经理**：需求判断依据（数据/调研）、上线后的指标验证、跨团队推动案例；B 端写客户规模与续约率，C 端写用户量级与留存。
- **用户增长**：渠道 ROI 对比、裂变/投放实验的具体数字、增长模型假设与验证过程。
- **内容运营**：爆款案例（阅读/播放量+粉丝转化）、内容供给体系搭建、选题方法。
- **电商运营**：大促操盘（GMV、备货、转化漏斗）、类目增长、直播/私域数据。

## 加分项与红线
- 加分：作品集/复盘文档链接、公众号或知乎有干货输出、独立做过 side project（小程序/社群）。
- 红线：把团队成果写成个人成果（面试一问细节就穿帮）、指标无基数（只写"提升了 300%"不写从多少到多少）、罗列日常职责没有结果。
- 「负责XX的日常运营」这类描述必须全部改写为具体动作+结果。

## 校招特别规则
- 实习含金量 > 一切；两段相关实习是最强配置。
- 学生会/社团经历只保留能量化的（办了 XX 人规模活动、公众号涨粉 XX）。
- 没有实习时：用个人项目补位（运营一个账号从 0 到 XX 粉丝的完整复盘比任何课程证书有说服力）。
