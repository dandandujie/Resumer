# 岗位画像：互联网技术岗

> 后端/前端/客户端/算法/测试/SRE 等技术岗位的简历定向优化知识。做技术岗简历前必读。

## 筛选者是谁
- 一面通常是未来的直属 TL（技术人看技术人），HR 只做硬性条件初筛。这意味着：**技术细节的真实性和深度比措辞华丽重要得多**。
- 大厂机筛+HR 初筛看：学历层级、公司背景（大厂/知名独角兽加权）、技术栈关键词命中、年限与职级匹配。

## 经历写法
- 每段经历/项目遵循「业务背景一句话 → 技术方案与个人职责 → 量化结果」：
  - 弱：负责订单系统开发和维护
  - 强：主导订单系统重构（日均 200w 单），引入 Kafka 削峰 + 本地缓存，大促峰值 3w QPS 下 P99 从 800ms 降至 120ms
- 量级词汇是技术简历的硬通货：QPS/TPS、DAU/MAU、数据量级（亿级表）、集群规模、P99 延迟、可用率（99.9x%）、降本金额/百分比。
- 技术栈精确到场景：不写「熟悉 Redis」，写「基于 Redis 实现分布式锁与热点缓存（缓存击穿防护）」。
- 「精通」只留给能手写实现/讲原理源码的技术；面试官会按简历深挖到底。

## 分方向侧重
- **后端**：架构设计与权衡（为什么选 MQ/为什么分库分表）、稳定性建设（限流、熔断、灰度）、性能优化案例。
- **前端**：性能指标（首屏/LCP 优化前后数据）、工程化（构建提速、组件库/脚手架建设）、跨端方案。
- **算法**：论文（会议等级）、竞赛（ACM/Kaggle 名次）、模型上线后的业务指标提升（不只是离线 AUC）。
- **测试/QA**：自动化覆盖率提升、效率工具建设、线上缺陷率下降数据。
- **SRE/运维**：可用率承诺与达成、故障复盘机制、容量与成本优化金额。

## 加分项与红线
- 加分：有 star 的开源项目、技术博客/专栏、专利、内部晋升记录（一年内晋升写出来）。
- 红线：技术栈罗列超过 15 个（显得样样不精）、写已淘汰技术（jQuery/SVN 除非岗位要求）、项目描述与年限不符（3 年经验写"架构了整个中台"会被质疑）。
- GitHub 链接只在有真实内容时放；空仓库/fork 仓是减分项。

## 校招特别规则
- 顺序：教育背景 → 实习 → 项目 → 技能。大厂实习 > 项目 > 课程设计。
- 项目要有区分度：课设烂大街项目（图书管理系统、外卖平台克隆）必须换成有个人洞察的项目或竞赛。
- 绩点 top 30% 才写；有 ACM/蓝桥杯等竞赛名次前置。
